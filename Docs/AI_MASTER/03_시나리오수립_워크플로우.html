핵심 사용자 시나리오

SC-001

신규 업무 요청 → Task 생성

새로운 업무 요청 Mail을 분석하고 기존 관련 Task가 없으면 신규 Task를 생성한다.

Mail → Analyze → Match 없음 → CREATE_TASK → DB → Dashboard
Input 신규 업무 요청 Mail
Output TODO 상태의 신규 Task
핵심 Value 업무 요청 누락 및 수동 등록 감소
SC-002

후속 Mail → 기존 Task 상태 갱신

기존 Task와 후속 Mail의 관계를 판단하여 기한·요청사항·회신대기·완료 상태를 갱신한다.

Follow-up Mail → Task Match → UPDATE / WAITING / COMPLETE → History
Input 기한 변경·자료 요청·자료 회신·완료 Mail
Output 기존 Task 변경 및 History
핵심 Value 업무 Lifecycle의 지속적 추적
SC-003

판단 불명확 → 사용자 확인

연관 Task 후보가 여러 개이거나 의도가 모호하면 Agent가 임의로 변경하지 않고 사용자에게 확인한다.

Ambiguous Mail → Candidate Tasks → ASK_USER → User Decision → DB
Input 모호한 요청·기한·완료 표현
Output 후보 Task와 선택 가능한 Action
핵심 Value Human-in-the-loop로 오판 방지

Agent Action

CREATE_TASK UPDATE_TASK LINK_TO_TASK SET_WAITING MARK_COMPLETED ASK_USER IGNORE

시나리오 우선순위 매트릭스

시나리오비즈니스 가치구현 난이도PoC 포함
SC-001 신규 업무 요청 메일의 Task 자동 생성높음중간예
SC-002 후속 메일 기반 기존 Task 연결 및 상태 갱신높음높음예
SC-003 판단이 불명확한 메일의 사용자 확인높음중간예
Agentic AI 핵심: 현재 Mail만 보는 것이 아니라 기존 Mail Context와 Task State를 함께 분석해 다음 Action을 결정하고, 변경된 State를 다음 Mail 판단에 다시 활용한다. SC-001~003은 별도 기능을 중복 구현하지 않고 M-01~M-05를 재사용한다.
