# 01. 역량 및 기술 스택

## 1. AI Master 목표와 프로젝트 적합성

AI Master Project 7기는 본인 업무와 직접 연관된 비즈니스 문제를 AI로 해결하고, 문제 정의부터 기본 Agent PoC, 정량 테스트, E2E 서비스, 최종 발표까지 8주 동안 수행하는 과정이다. Lv.3 핵심 역량에는 Agent 이해 및 Workflow 구현, 도메인 AI 시스템 개발, 소규모 AI 프로젝트의 독립 수행이 포함된다.

MailTaskAgent는 메일 한 건을 분류하는 데서 끝나지 않는다. 새로운 메일과 현재 Task 상태, 선행·후행 Mail Context를 함께 분석하고 7가지 Action 중 다음 행동을 선택한 뒤 변경된 상태를 다음 판단에 다시 활용한다. 따라서 상태(State), 문맥(Context), 행동(Action), 재판단(Loop)을 갖는 Agentic AI 과제로 정의한다.

## 3. 확정 기술 스택

### 멘토 리뷰용 Vertical Slice와 초기 PoC

| 영역 | 기술 | 역할 |
|---|---|---|
| 언어 | Python 3.11 또는 사내 허용 버전 | Agent와 Application Logic |
| Web UI | Streamlit | Mail 선택, Agent 판단, Task Dashboard |
| 데이터 검증 | Pydantic | LLM 구조화 출력과 상태 모델 검증 |
| LLM 통신 | requests 또는 httpx | 사내 LLM API/개발용 LLM 호출 |
| Database | Python `sqlite3` + SQLite | Mail, Task, 변경 History 저장 |
| 설정 | 환경 변수, python-dotenv 선택 | URL, Key, Model, DB 경로 분리 |
| 테스트 | pytest | 단위·통합·E2E 검증 |
| 입력 | 합성·비식별 JSON Mail Dataset | 재현 가능한 개발·평가 |

### 선택적 고도화

- LangGraph: Node·Edge·State 분기가 복잡해져 실익이 확인될 때만 도입한다.
- Microsoft Graph/Outlook: 사내 권한이 확보되면 Read-only Mail Input Adapter로 추가한다.
- n8n: Agent 판단이 아닌 Mail Polling, 일정 확인, Reminder 같은 정형 자동화에만 사용한다.
- 사내 서버/VM: 다중 사용자 또는 상시 실행이 필요해질 때 검토한다.

RAG, Vector DB, Multi-Agent, FastAPI, PostgreSQL은 현재 문제 해결에 필수적이지 않으며 초기 구현 범위에서 제외한다.

## 4. 개발 환경 원칙

- 1차 개발은 사내 VDI에서 Python, SQLite, Streamlit을 실행하고 같은 VDI 브라우저의 `localhost:8501`로 확인한다.
- 별도 개발 VM이나 VirtualBox는 8주 PoC의 필수조건이 아니다.
- 사내 LLM API 접근이 불가능한 로컬 환경에서는 합성 데이터와 Mock/허용된 개발용 LLM으로 Core를 개발하고 LLM Client만 교체한다.
- 실제 업무메일은 개인 PC로 이동하지 않는다.
