## 5. 왜 Agentic AI인가

이 프로젝트의 모든 부분에 LLM을 억지로 사용하지 않는다. 동일 Thread와 중복 Mail처럼 확정 가능한
경로는 규칙으로 처리한다. Agentic AI가 필요한 지점은 표현이 달라진 Mail과 기존 Task의 관계,
다음 Action, 필요한 회신 방식처럼 규칙을 모두 열거하기 어려운 판단이다.

Agent는 현재 Mail과 검색된 Task·Mail·History를 관찰하고 관계·대상·Action을 제안한다. 저신뢰이면
검색 Query를 한 번 수정해 다시 관찰하고, 그래도 모호하거나 Python Guard와 충돌하면 사용자에게
결정을 넘긴다. 승인된 Action을 실행한 뒤 실제 DB·Gmail 결과를 다시 관찰한다. 이 때문에 구조는
단순 `메일 → 분류`가 아니라 `Observe → Retrieve → Decide → Reflect → Guard → Act → Observe`다.

회신 기능도 단순 문장 생성이 아니다. Reply Agent가 `NO_REPLY`, `SIMPLE_ACK`, `DATE_REPLY` 등
회신 방식과 필요한 사용자 입력을 먼저 선택하고, 회사 LLM이 그 입력과 Thread Context로 초안을
만든다. Allowlist·Thread·중복 발송 Guard와 사용자 승인을 통과한 경우에만 Gmail Tool을 실행한다.
