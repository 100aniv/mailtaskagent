## 4. Agentic AI로 설명할 핵심

실제 시연에서는 단순히 “메일을 분류했다”라고 설명하지 않는다. 다음 판단·행동 구조를 화면과 함께 설명한다.

```text
실제 Gmail Mail 관찰
→ LLM이 Intent·요청·기한과 신뢰도 구조화
→ 관련 Task·Mail·History Context 검색
→ Agent가 관계와 다음 Action 제안
→ Python Guard가 상태 전이와 위험 변경 검증
→ 안전하면 DB 실행, 위험·불확실하면 ASK_USER
→ 실행 결과를 다시 조회해 실제 저장 상태 확인
→ 필요 시 Reply Agent가 회신 방식과 초안 제안
→ 사용자가 승인해야 Gmail 발송
→ 발송 결과를 관찰하고 WAITING_REPLY로 전환
```

LLM은 의미 판단과 Action 제안을 담당하며, Python은 제안 내용을 안전하게 검증한다. 이 분리가 단순 Rule Workflow와 다른 Agentic AI의 핵심이면서 실제 Mail을 안전하게 다루는 장치다.

## 6. 오늘 검증의 정확한 해석

- 오늘 동기화 시점의 신규 Mail은 0건이었다.
- 조회된 23건은 실제 Gmail Mail이지만 이미 처리된 Mail을 포함한다.
- 동기화 명령은 23건 모두에서 기존 결과를 정상 반환했고 실패는 0건이었다.
- 기존 Mail은 중복 방지 정책 때문에 LLM과 DB를 다시 실행하지 않았다.
- 신규 Mail이 도착하면 1분 자동 실행 주기에서 새 Agent Trace와 Task 반영 결과가 생성된다.
- 따라서 다음 주 현장 시연 전에는 새 테스트 Mail 한 건을 미리 준비하거나, 발표 직전에 발송해 최대 1분의 수집 시간을 확보한다.

## 7. 결론

Gmail 실제 모드에서 수신, Task 생성, 후속 Mail 연결, 위험 변경의 사용자 확인, AI 회신 판단, 사용자 승인 발송, 발송 후 회신 대기 전환까지 E2E 근거가 확인됐다. 다음 주 시연에서는 합성 시나리오가 아니라 실제 Gmail Task와 Agent Trace를 우선 사용한다.
