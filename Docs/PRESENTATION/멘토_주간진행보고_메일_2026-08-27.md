## 메일 본문

안녕하세요, 멘토님.

어제 피드백 미팅을 진행하지 못해 MailTaskAgent의 현재 구현 현황을 자료와 데모 영상으로 먼저 공유드립니다.

MailTaskAgent는 메일을 단순 요약·분류하는 서비스가 아니라, 새 메일과 기존 Task 상태를 함께 보고 다음 Action을 결정한 뒤 Validation, 필요 시 사용자 확인, Task/History 저장까지 연결하는 Agentic AI 프로젝트입니다.

현재까지 다음 Core E2E를 구현했습니다.

- 회사 제공 LLM API(`gpt-4.1-mini`)를 이용한 Mail 의미·Intent 구조화
- M-01 Mail Analyzer → M-02 Task Matcher → M-03 Action Decision → M-04 Task/History → M-05 Review/Dashboard 연결
- 7개 Agent Action: `CREATE_TASK`, `UPDATE_TASK`, `LINK_TO_TASK`, `SET_WAITING`, `MARK_COMPLETED`, `ASK_USER`, `IGNORE`
- 5개 Task Status와 SQLite 기반 상태·변경 이력 관리
- 완료·취소·기한 단축·복수 후보 등 중요하거나 애매한 변경의 Human-in-the-loop 처리
- Streamlit 업무 현황, 메일 처리함, 확인 필요, 운영 로그, 품질 검증 화면
- API Key·Authorization Header 등 Secret 정보의 UI·로그·DB 비노출

LLM은 Mail의 의미와 Intent만 구조화하고, 기존 Task 후보 검색과 최종 Action 결정은 Python Application Logic이 수행하도록 책임을 분리했습니다. 실제 DB 변경은 Schema·상태 전이 검증을 통과한 결과에만 허용하며, `ASK_USER` 대상은 사용자 결정 전 중요 변경을 반영하지 않습니다.

현재 검증 결과는 아래와 같습니다.

- 회사 LLM Live 평가: 15/15 Case 통과
- Action 단계 일치: 28/28
- 실행 오류: 0건
- Live 15개 평가 총 처리시간: 53.955초
- 자동 테스트: pytest 42 passed

위 수치는 현재 정의한 합성·비식별 Dataset의 E2E Action 결과입니다. 업무 분류 정확도, 핵심 필드 정확도, Task ID 매칭 정확도, 사람 수동 처리시간 Baseline과 비용 KPI는 아직 별도 측정이 남아 있어 완료 수치로 작성하지 않았습니다.

현재 UI의 일괄 처리 버튼은 합성 Mail 15건의 유입을 재현하는 데모 Trigger입니다. 실제 운영 구조에서는 Mail Input Adapter가 신규 메일을 전달하면 Agent Core가 자동 실행되므로 사용자가 메일마다 분석 버튼을 누르는 방식은 아닙니다. Core 마감과 KPI 검증 이후 일정이 남을 경우 테스트 Gmail Adapter를 검토하고, Outlook/Microsoft Graph, n8n과 사내 운영환경은 Post-MVP로 유지할 계획입니다.

첨부 자료에는 Node/책임 분리, Action·Status 모델, 3개 사용자 시나리오와 15개 검증 Case, 현재 UI와 운영 로그, 검증 증적, TO-BE 운영 UI 및 다음 단계가 포함되어 있습니다. 데모 영상은 기능 흐름을 재현 가능하게 보여주기 위해 합성 Mail과 Mock 분석 결과를 사용했으며, 회사 LLM Live 결과는 PPT의 별도 검증 증적으로 표시했습니다.

가능하실 때 아래 세 가지에 대해 의견 부탁드립니다.
